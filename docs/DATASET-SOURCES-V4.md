# Official source assessment for V4

ListProof currently commits **synthetic** addresses. No official sanctions feed is imported, classified verified, or published on-chain. A non-membership proof only concerns the set actually committed.

| Source | Authenticity and format | EVM address suitability | Decision |
|---|---|---|---|
| [US OFAC Sanctions List Service](https://ofac.treasury.gov/sanctions-list-service) | Official SDN and non-SDN downloads, including machine-readable products; OFAC publishes hashes for content assurance. [Technical notice](https://ofac.treasury.gov/sdn-list-data-formats-data-schemas/ofac-technical-actions-in-reverse-chronological-order/20240516_44) describes the SLS export host and User-Agent requirement. | OFAC's [FAQ 563](https://ofac.treasury.gov/faqs/563) confirms `Digital Currency Address - ETH` fields. They are a subset of all sanctions data and can change or be delisted. | Best candidate for a future reviewed adapter. No automatic source fetch or parser is enabled. |
| [EU consolidated financial sanctions list](https://finance.ec.europa.eu/eu-and-world/sanctions-restrictive-measures/overview-sanctions-and-related-resources_en) | Official Commission list updated when necessary; primarily person/entity designations. | No general, documented EVM address feed was established in this research. | Do not transform names into wallet claims. |
| [UN Security Council consolidated list](https://main.un.org/securitycouncil/en/content/un-sc-consolidated-list) | Official XML, HTML and PDF list of people and entities. | No general, documented EVM address feed was established in this research. | Useful provenance reference, not an address commitment source yet. |

OFAC's [flat-file tutorial](https://ofac.treasury.gov/sdn-list-data-formats-data-schemas/tutorial-on-the-use-of-list-related-legacy-flat-files) warns that one CSV alone omits linked identifiers and aliases. For the product's **narrow ETH-address set**, a parser must establish exactly which OFAC fields were extracted and retain source record IDs, full raw bytes, published hash, retrieval time and parser version. A single official source cannot provide universal sanctions coverage. Download/reuse terms, redistribution and operational refresh policy require owner/legal review before a real feed is distributed or marketed.

`src/source-snapshot.mjs` is a tested **transport boundary**, not a sanctions parser. It accepts bytes from an allowlisted HTTPS OFAC host and a pinned SHA-256, rejects mismatches and unsafe URLs, and returns `classification: imported-unverified`, `readyForPublication: false`. It does not extract addresses or assert that a claimed source hash was published by OFAC. No `verified-source` label is issued. This keeps the existing synthetic dataset separate while providing a safe interface for a future reviewed extractor.
